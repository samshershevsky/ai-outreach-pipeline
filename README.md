**Live site:** https://samshershevsky.github.io/ai-outreach-pipeline/

## Overview

I build production AI agents for revenue teams, and this repo is the portable, runnable version of that work. A CSV of synthetic leads goes in, and enrichment, transparent scoring, and grounded outreach drafts come out. An orchestrator agent on Claude coordinates specialized sub agents, every tool call goes through a custom MCP server, drafts stop at a human approval step before anything is sent, and an evals suite checks scoring, rubric math, and draft grounding on every push. Nothing here uses real data: the 25 leads are fictional, enrichment is a deterministic simulation, and the architecture, rubric, prompts, and evals are the real thing.

## Quickstart

Everything runs on the Python 3 standard library. There is nothing to install.

Run the pipeline:

```bash
bash demo/run.sh
```

It prints each stage and writes `demo/output/report.md`, `demo/output/scored_leads.csv`, and `demo/output/outreach_emails.md`. Options: `bash demo/run.sh --min-score 55` drafts only for qualified leads. The real captured log of a run is at `demo/output/run.log`.

Run the evals:

```bash
python3 evals/run_evals.py
```

The evals check scoring consistency across repeated runs, rubric correctness with a reason string for every point, draft grounding against each lead's own signals, and tool call success and latency across 25 synthetic leads. Results land in `evals/results.json`, and the same script runs in CI on every push. It exits nonzero if any check fails.

Run the demo MCP server:

```bash
python3 mcp-server/server.py
```

The server, named **gtm-pipeline-mcp**, speaks MCP over stdio and exposes four tools: `enrich_lead`, `score_lead`, `draft_outreach`, and `get_report`. See [`mcp-server/README.md`](mcp-server/README.md) for how to connect it to Claude.

Want live Claude drafting instead of the built in template engine in the demo? Set `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL`, and the pipeline executes the exact prompts in `demo/prompts.py` against the API.

## Design choices worth knowing

- **Explainable scoring.** Every point has a reason string in `demo/scoring.py`, so a human or a reviewer agent can audit why a lead is Tier A. Black box scores do not survive contact with a sales team.
- **Prompts as code review.** Outreach prompts live in `demo/prompts.py`, not buried in logic: versioned, reviewable artifacts, the same practice I use in production.
- **Human in the loop by design.** The pipeline ends at drafts, not sends. The approval gate is a feature, not a missing piece.
- **Deterministic demo, live capable core.** The template engine means anyone can run this with no keys. The Claude path uses the identical prompts, so what you see is what production gets.
- **Evals before trust.** If a check in `evals/` fails, the fix goes into the pipeline, never into hiding the result.
